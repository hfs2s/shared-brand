Page anatomy

Give every page a predictable reading order. Use the same page frame when the layout changes from a collection to a detail view or settings.

  1. Shared shell

    Provide the skip link and product navigation. Highlight the current section and keep deep links shareable.

  2. Page heading

    Use one page title. Add a parent link when the page is nested and put the main action beside the title, or just below it on phones.

  3. Local navigation

    Use the shared menu for peer views. Keep the active label visible and place its content immediately below.

  4. Main content

    Use one labelled main landmark. Give the primary content the available width, then place optional context beside it or below it on phones.

  5. Feedback and recovery

    Keep loading, empty, error, and success messages in the region they describe. Preserve context, choices, and drafts when someone retries.

Use the Shared width, gutter, section spacing, and control-height tokens. Keep visual, reading, and keyboard order aligned at every width. Add a footer where the surface needs persistent secondary links.
