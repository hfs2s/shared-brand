Build and nest the grid

Line up the shell
Align the page title, stage, and action bar to the parent grid. Subtract any navigation rail before deciding the number of content columns.
Keep consistent gutters
Use the page gutter once at the outside of the page. Use the grid gap between regions. Use a card’s internal padding for its own label and content.
Nest by purpose
Use subgrid when a child needs to share its parent’s track lines. Use a local wrapping grid for repeatable cards with a minimum readable width.
Use the available width
Use zero-minimum fractional tracks for columns that can shrink and let long words wrap inside them. Reserve fixed widths for controls or media that actually need them.

Start with a named container

Use width-based column changes in the page composition. A split pattern can set its own medium and wide spans without changing the base grid.

.page-content { container: page-content / inline-size; }
.page-grid {
  --columns: 4;
  display: grid;
  grid-template-columns: repeat(var(--columns), minmax(0, 1fr));
  gap: var(--content-gap);
}
@container page-content (min-width: 640px) {
  .page-grid { --columns: 8; }
}
@container page-content (min-width: 1024px) {
  .page-grid { --columns: 12; }
}

Spans and spacing

Narrow · 4 columns
Below 640 px of available width, let the page regions span all four columns and stack in reading order.
Medium · 8 columns
At 640 px, use eight columns. Give work and supporting context a 5 + 3 split when each remains readable.
Wide · 12 columns
At 1024 px, use twelve columns. Use an 8 + 4 split for work and context. Keep headings and task actions aligned to the page grid.
Gutters, gaps, and reading width
Use --gutter for the page edge, --content-gap between page regions, and --wrap-max for the outer width. Limit long text to about 65–72 characters per line.

Measure the content area after a sidebar takes its space. Let card grids wrap according to their minimum usable width. The paper texture uses --grid-step independently of the layout columns.
